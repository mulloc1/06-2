# 평가 문항 13 · max_tokens

## 답변

`max_tokens`는 모델이 생성하는 **출력** 토큰의 상한이다. 너무 작으면 커밋 본문이나 PR의 뒷부분, 특히 `How to Test`가 중간에서 잘려 필수 형식을 잃을 수 있다. 너무 크면 불필요하게 긴 응답, 비용, 지연이 늘 수 있다.

입력 컨텍스트와 출력 예산은 구분해야 한다. 이 도구는 입력 diff를 12,000자로 제한하고, 출력은 commit 400·pr 700 토큰을 기본값으로 둔다. 출력이 잘렸다면 `--max-tokens`를 올리는 것이 도움이 되지만, 입력 diff가 이미 잘렸다면 출력 한도를 늘려도 모델이 보지 못한 변경은 복구되지 않는다. 즉 `max_tokens`는 입력 맥락 유지 자체를 해결하는 옵션이 아니다.
