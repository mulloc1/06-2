# AI Git CLI 평가 문항

## 평가 개요


| 항목    | 초점       | 평가 방식                                  |
| ----- | -------- | -------------------------------------- |
| **1** | 기능·동작 검증 | 커밋/PR 생성, 환경·에러, 파라미터 옵션 동작            |
| **2** | 설계·구조 설명 | 책임 분리, 프롬프트/후처리, 옵션화 근거                |
| **3** | 핵심 개념 이해 | temperature·max_tokens, 재생성 vs 후처리, 한계 |


---

## 항목 1 · 기능·동작 검증

> CLI 실행 결과와 코드로 요구사항 충족 여부를 확인합니다.

### 커밋 메시지 생성

- **기준 1**
커밋 포맷이 프롬프트에 반영되고, AI 결과가 표준출력으로 출력되며, 검토 후 적용하라는 안내가 있는가?

### PR 초안 생성

- **기준 2**
PR 제목·본문 형식의 초안이 터미널에 출력되고, 초안임이 명시되는가?

### 환경변수·인증

- **기준 3**
API 키 환경변수 누락 시 원인을 포함한 오류 메시지가 출력되는가?



### 변경사항 없음

- **기준 4**  
Git 변경사항이 없을 때 명시적 메시지를 출력하고 정상 종료하는가?



### PR 본문 구조

- **기준 5**  
PR 본문에 Why / What / How to Test 섹션이 포함되는가?



### API 파라미터 옵션

- **기준 6**  
`temperature`, `max_tokens` 등 API 파라미터를 CLI 옵션으로 변경할 수 있는가?



### 출력 포맷 규칙

- **기준 7**  
커밋 제목 길이·본문 불릿 등 포맷 규칙이 프롬프트 또는 검증에 반영되는가?



### API 예외 처리

- **기준 11**  
API 키 누락, HTTP 에러(401/429), 네트워크·타임아웃을 구분해 처리하는가?



### 프롬프트 맥락

- **기준 14**  
프롬프트에 변경 파일 목록과 diff를 포함해 충분한 맥락을 제공하는가?

---



## 항목 2 · 설계·구조 설명

> 구조 선택과 분리 이유를 설명할 수 있는지 확인합니다.



### 책임 분리

- **기준 8**  
Git 수집과 AI 호출의 책임 분리, 그리고 유지보수·테스트 전략을 설명할 수 있는가?



### 프롬프트 vs 후처리

- **기준 9**  
프롬프트와 출력 후처리를 분리한 이유와 설계를 설명할 수 있는가?



### 파라미터 옵션화

- **기준 10**  
API 파라미터를 옵션화한 이유(재현성·실험·CLI 활용)를 설명할 수 있는가?

---



## 항목 3 · 핵심 개념 이해

> 파라미터 영향, 품질 전략, AI 한계를 이해하고 있는지 확인합니다.



### temperature

- **기준 12**  
`temperature`가 결과의 무작위성·창의성에 미치는 영향과, 언제 높거나 낮은 값을 쓰는지 설명할 수 있는가?



### max_tokens

- **기준 13**  
`max_tokens`가 출력 길이·컨텍스트 유지·절단 위험에 미치는 영향을 설명할 수 있는가?



### 재생성 vs 후처리

- **기준 15**  
출력 품질 문제 시 재생성과 후처리 중 어떤 전략을 택할지, 그 근거를 설명할 수 있는가?



### AI 한계·검토

- **기준 16**  
AI 생성 텍스트의 오류·편향 가능성과 수동 검토 필요성을 안내할 수 있는가?
